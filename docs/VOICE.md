# Voice entry in Hindi and English

Voice input uses Streamlit's native microphone recorder and Gemini audio
transcription. It joins the same case workflow as typed input; a transcription
is not a legal answer or an automatic acceptance of the facts it contains.

## Use the microphone

1. Expand **Tell your story by voice · हिन्दी / English** and choose **Spoken
   language**: Auto, Hindi, English or Hinglish. Speak naturally; Hindi and English
   may be mixed in the story.
2. Allow microphone access when the browser asks, record a short story, then
   stop. The recorder produces a WAV held by the app's server session.
3. Select **Transcribe recording**. The server sends that recording to Google
   Gemini using its server-side API key.
4. Edit **Review your transcript**, especially names, dates and amounts. Hindi
   should stay in Devanagari when spoken in Hindi; transcription is not intended
   to translate the story into another language.
5. Select **Use this transcript**. Only that reviewed text is used to
   update the case and choose the next question.

Recording alone must not update a case, send a message to the other party, or
file anything. A failed transcription must leave the case unchanged. Type the
story instead if recording or recognition is unavailable.

## Browser and hosting requirements

Microphone capture needs browser permission and a secure context: use the
deployed HTTPS Render URL or local `localhost` / `127.0.0.1` preview. A plain
HTTP address on a remote or LAN host may not offer microphone capture. Check
the browser's site permissions and operating-system microphone permission if
the recording control cannot access a device.

The current server path accepts recordings up to two minutes and 10 MiB. Short
recordings are easier to review. No speech, a provider limit, an unavailable
model or an authentication problem must produce an actionable message, not an
invented transcript.

## Configure Gemini

Set `NYAYA_PROVIDER=gemini`, `GEMINI_MODEL=gemini-3.5-flash-lite` or another available audio-capable model,
and `GEMINI_API_KEY` in the local ignored `.env` or Render's secret environment
settings. Do not put the key in a browser field, source file or submission
archive. The configured key and model must support both structured text
extraction and audio input. A successful configuration label is not evidence
that a specific transcription succeeded.

## Privacy and verification limits

The app keeps real recordings and draft transcripts in server session memory;
it does not intentionally save them as project artifacts. Google receives the
audio when transcription is requested and receives reviewed case text in AI
mode. Its data handling follows the API account's terms and settings. Clearing
the case clears the app's session controls; it does not erase any provider logs.

Only original synthetic recordings belong in `evaluation/audio/`. The English
deposit fixture is generated from an original sentence using an installed
Microsoft David Windows SAPI voice, not a human participant. Its metadata and
generation script record that provenance. A synthetic-voice test does not
establish accuracy for every accent, noisy environment or real microphone.
An actual English transcription run succeeded in **3.01 seconds** using
`gemini-3.5-flash-lite`; it converted the spoken words “twelve thousand” to
`12000`, illustrating why the review step matters. Its raw response and token
usage are in
[`gemini_english_voice_20261121T140012353451Z.json`](../raw_outputs/gemini_english_voice_20261121T140012353451Z.json).
The Hindi synthetic fixture was generated by Gemini TTS from original Hindi
text and then transcribed in **2.794 seconds**. The transcription retained the
12,000 amount and receipt but changed a possessive phrase and omitted the spoken
rupee unit. It was usable for review, not word-perfect. Its metadata records the
TTS provenance, and its actual result is
[`gemini_hindi_voice_20261121T140623277162Z.json`](../raw_outputs/gemini_hindi_voice_20261121T140623277162Z.json).
These measured runs are separate from mocked tests and
typed-message evaluations; they do not establish accuracy for every accent or
recording condition.
